# Twitter Memo

X 사용자 프로필에 개인 메모를 남기는 Manifest V3 확장 프로그램입니다. 메모는 이 기기의 `chrome.storage.local`에 저장하며, 외부 서버나 X API로 전송하지 않습니다.

## 사용

1. X 프로필을 열고 확장 프로그램 아이콘을 누릅니다.
2. 현재 `@핸들`과 저장된 메모를 확인하고 내용을 수정합니다.
3. 저장하면 프로필 표시와 메모 목록에 반영됩니다. 빈 내용으로 저장하면 해당 사용자의 메모를 삭제합니다.

게시물·답글·재게시·미디어·아티클 탭에서 같은 사용자 메모를 사용합니다. 홈, 검색, 개별 게시물 등 프로필이 아닌 페이지에서는 저장할 수 없습니다. 프로필이나 기존 메모를 읽지 못한 경우에도 저장을 막고 오류를 표시합니다.

메모 목록의 프로필 링크는 숫자 사용자 ID로 열립니다. 핸들이 바뀌어도 메모는 같은 사용자 ID에 연결됩니다.

## 타임라인에서 메모 보기

메모를 저장한 사용자의 게시물에는 타임라인에서도 메모가 표시됩니다. 같은 작성자의 여러 게시물, 스크롤로 새로 나타난 게시물에 적용되며, 메모 수정·삭제도 반영됩니다. 인용된 사용자나 본문 멘션을 게시물 작성자로 취급하지 않습니다.

타임라인에는 숫자 사용자 ID가 없어, 프로필에서 확인한 ID와 핸들 연결을 사용합니다. 메모 자체는 계속 숫자 ID별로 저장합니다. 연결 정보는 메모가 있는 사용자에 대해서만 저장하며, X API 추가 조회나 쿠키 접근을 하지 않습니다.

이전 버전의 메모에 핸들이 연결되지 않았다면 메모 목록의 **프로필 열기**로 해당 프로필을 한 번 방문하세요. 이후 타임라인에서 그 사용자의 메모를 볼 수 있습니다. 핸들 변경이나 재사용도 프로필에서 다시 확인한 뒤 연결을 갱신합니다. 확인 전까지 타임라인 표시는 마지막으로 확인한 핸들에 의존합니다.

## 설치와 업데이트

Chrome 102 이상을 대상으로 합니다. 소스 수정 후 별도 빌드 없이 저장소 루트를 확장 프로그램으로 사용할 수 있습니다.

1. Chrome에서 `chrome://extensions`를 열고 개발자 모드를 켭니다.
2. **압축해제된 확장 프로그램을 로드합니다**에서 이 저장소 폴더를 선택합니다.
3. 코드 변경 후에는 기존 확장 프로그램 항목의 **새로고침**을 누르고, 열려 있던 X 페이지도 새로고침합니다.

기존 메모는 확장 프로그램 ID에 연결된 저장소에 있습니다. 메모를 유지하려면 기존 확장을 삭제하지 않고 같은 ID로 업데이트해야 합니다. 웹 스토어판과 소스에서 직접 로드한 확장은 ID가 다를 수 있으며, 이 경우 메모가 자동으로 옮겨지지 않습니다.

## 권한과 저장 형식

- `storage`: 기기 내 메모 저장과 변경 감지
- `activeTab`: 사용자가 팝업을 열었을 때 현재 탭의 프로필 확인
- 콘텐츠 스크립트: `https://x.com/*`, `https://twitter.com/*`에서 실행

기존 형식인 `{ "숫자 사용자 ID": "메모 문자열" }`을 유지합니다. 큰 사용자 ID도 문자열로 다뤄 정밀도를 잃지 않습니다. 확장 프로그램을 업데이트할 때 기존 데이터를 일괄 변환하거나 삭제하지 않습니다.

타임라인 표시를 위한 핸들 연결은 숫자 메모 키와 구분되는 별도 메타데이터에 저장합니다.

프로필에 표시하는 메모는 해당 페이지의 DOM에 삽입됩니다. 페이지 안의 스크립트에서도 표시된 내용을 읽을 수 있습니다.

## 개발과 검증

Node.js 24를 사용합니다. 실행 코드에는 외부 패키지나 번들러가 필요하지 않으며, jsdom은 자동 테스트용 개발 의존성입니다.

```sh
nvm use
npm ci
npm run check
npm test
```

`npm run check`는 JavaScript 문법, manifest가 참조하는 파일, manifest/package 버전 일치를 확인합니다. `npm test`는 jsdom으로 DOM 동작을 실행하며 브라우저 확장 API를 모의합니다. 실제 브라우저의 렌더링·확장 실행 환경과는 구분합니다. GitHub Actions에서도 같은 검증을 수행합니다.

자동 회귀 검증 범위에는 현재·기존 JSON-LD 구조, 숫자 ID 보존, 지연 로딩, SPA 프로필 이동, 늦은 응답 차단, 안전한 텍스트 표시, 저장·삭제와 오류 처리가 포함됩니다.

수동 확인 순서:

1. 프로필을 직접 열어 기존 메모를 확인하고 수정·저장합니다.
2. 홈 → 다른 프로필 → 뒤로/앞으로 → 프로필 하위 탭으로 이동하며 메모 대상을 확인합니다.
3. 새로고침 후 메모 보존과 빈 메모 삭제를 확인합니다.
4. 홈·검색·개별 게시물·다른 사이트에서 팝업을 열어 저장이 차단되는지 확인합니다.
5. 메모가 있는 프로필을 확인한 뒤 홈·프로필 타임라인으로 이동합니다. 해당 작성자에게만 메모가 표시되고 스크롤·수정·삭제 후에도 올바른 상태인지 확인합니다.

실제 Chrome에서 설치한 확장의 동작 검증은 자동 테스트와 별도로 수행해야 합니다.

[Chrome 수동 검증 기록](docs/chrome-verification.md)을 참고하세요.

## 구조

- `scripts/shared.js`: 프로필 URL·사용자 ID 등 공통 규칙
- `scripts/content.js`: 현재 프로필 확인, 프로필·게시물의 메모 표시, 페이지 이동과 저장소 변경 감지
- `scripts/background.js`: 메모 읽기·쓰기·목록 메시지 처리
- `scripts/popup.js`, `popup.html`, `styles.css`: 메모 편집과 목록
- `tests/`: 회귀 테스트
- `tools/check.mjs`, `.github/workflows/verify.yml`: 로컬·CI 검증

콘텐츠 스크립트가 확인한 현재 핸들, 표시된 핸들, JSON-LD의 사용자 정보가 일치할 때만 숫자 ID를 사용합니다. X의 DOM이나 JSON-LD 구조가 다시 바뀌어 프로필을 확인할 수 없으면 임의의 사용자에게 저장하지 않습니다.
