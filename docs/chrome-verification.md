## 타임라인 표시의 확인된 입력 구조

공개 X 프로필의 게시물에서 아래 구조를 확인했습니다.

- 게시물: `article[data-testid="tweet"]`
- 본문 작성자 헤더: `[data-testid="User-Name"]`
- 작성자 링크: `/<handle>`이며, 별도의 게시 시각 링크는 `/<handle>/status/<post ID>`입니다.
- 검사한 게시물에는 `[data-user-id]`가 없습니다.

따라서 숫자 ID별 메모를 그대로 유지하면서, 검증된 프로필에서 얻은 ID와 핸들 연결 정보로 타임라인 작성자를 찾습니다. 기존 메모처럼 핸들이 아직 연결되지 않은 경우에는 해당 프로필을 한 번 확인해야 합니다.

## 0.2.0 — 2026-10-27

같은 Chrome에서 확장 프로그램을 `0.2.0`으로 다시 로드하고, X 페이지 자체도 새로고침한 뒤 확인했습니다. 실제 팝업과 `chrome.storage.local`을 사용했으며, 게시물 DOM이나 저장소 응답을 테스트용으로 대체하지 않았습니다.

| 확인 항목 | 결과 |
| --- | --- |
| 프로필에서 저장한 메모를 게시물 작성자 아래 표시 | 통과, 처음 확인한 게시물 10곳에 표시 |
| 스크롤 후 새로 나타난 게시물에도 적용 | 통과 |
| 팝업 수정 후 타임라인의 기존 메모 갱신 | 통과, 표시된 14곳 갱신·이전 문구 제거 |
| 삭제 후 프로필·타임라인 표시 제거 | 통과, 메모 표시 0곳 |
| 실제 홈 게시물 작성자의 프로필 방문·저장 후 홈으로 복귀 | 통과, 해당 홈 게시물에 메모 표시 |
| 해당 메모 삭제 후 홈으로 복귀 | 통과, 테스트 문구 제거 |

테스트 메모는 모두 삭제했고, 확인용으로 연 탭도 닫았습니다. 기존 스토어판의 설정과 저장소는 변경하지 않았습니다. 개발 확장은 로드된 상태입니다.

이전 숫자 ID 메모의 연결, 핸들 변경·재사용, 동시 저장, 인용·멘션 구분, DOM 재사용과 저장 오류는 jsdom/확장 API 모의 회귀 테스트로 별도 검증했습니다. 기존 숫자 ID만 가진 메모를 실제 Chrome 저장소에 직접 주입하는 검증은 수행하지 않았습니다.
